# Дошка оголошень групи

Навчальний наскрізний проєкт з дисципліни **«Основи алгоритмізації та програмування»**.

Проєкт реалізує просту дошку оголошень для групи: користувач входить у систему, створює оголошення, переглядає список, редагує та видаляє власні записи, користується пошуком, фільтрацією, сортуванням і переглядає статистику за категоріями.

## Стек технологій

- **Backend:** Node.js, Express, TypeScript
- **База даних:** SQLite через вбудований модуль `node:sqlite`
- **Frontend:** HTML, CSS, JavaScript
- **Обмін даними:** Fetch API, JSON
- **Авторизація:** Bearer token
- **Безпека:** параметризовані SQL-запити, безпечний DOM-рендер, перевірка власника ресурсу, CORS, security headers

```text
    ├── server.ts              # точка запуску сервера

    ├── db.ts                  # підключення SQLite, схема БД, seed-користувачі

    ├── security.ts            # паролі, токени, CORS, security headers
```


## Тестові акаунти

Під час першого запуску база створюється автоматично, а в таблицю користувачів додаються тестові акаунти:

```text
admin@group.local  / Admin123!
anna@group.local   / User123!
bohdan@group.local / User123!
```

За замовчуванням створюються тільки користувачі. Оголошення та коментарі потрібно додавати вручну через інтерфейс.

## Безпека

У фінальній версії проєкту реалізовано базові захисні механізми.

### SQL Injection

SQL-запити виконуються через `prepare()` і параметри `?`, наприклад:

```ts
WHERE email = ?
```

Користувацькі значення не вставляються напряму в SQL-рядок.

### XSS

На frontend дані користувача вставляються в DOM через `textContent`, а не через `innerHTML`. Через це HTML або JavaScript, введений користувачем, відображається як текст і не виконується браузером.

### Broken Access Control / IDOR

Для операцій з конкретним оголошенням використовується перевірка власника ресурсу. Звичайний користувач може редагувати й видаляти тільки власні оголошення. Користувач з роллю `admin` має ширші права доступу.

### Security headers і CORS

Backend додає базові security headers:

```text
X-Content-Type-Options
X-Frame-Options
Referrer-Policy
Content-Security-Policy
```

CORS налаштований через allowlist для локального frontend-origin:

```text
http://localhost:5500
http://127.0.0.1:5500
```

## Security regression-перевірки

Файл для ручної перевірки security-сценаріїв:

```text
security-regression.http
```

Його можна запускати у VS Code через розширення REST Client.

У файлі перевіряються такі сценарії:

- логін користувачів;
- SQL Injection payload у пошуку;
- Stored XSS payload у тексті оголошення;
- спроба доступу до чужого оголошення;
- спроба редагування чужого оголошення;
- перевірка security headers;
- перевірка єдиного формату помилки.

Перед запуском перевірок backend має бути запущений командою:

```bash
npm run dev
```

## Змінні середовища

Проєкт підтримує такі змінні середовища:

```text
PORT          # порт backend-сервера, за замовчуванням 3000
DB_PATH       # шлях до SQLite-файлу, за замовчуванням data/posts-board.sqlite
TOKEN_SECRET  # секрет для підпису токенів
```

Для локального запуску `TOKEN_SECRET` має fallback-значення, але для production його потрібно обов’язково задавати через environment variable.

## Типовий сценарій перевірки роботи

1. Встановити залежності:

```bash
npm i
```

2. Запустити backend:

```bash
npm run dev
```

3. В іншому терміналі запустити frontend:

```bash
python -m http.server 5500
```

4. Відкрити сторінку:

```text
http://localhost:5500
```

5. Увійти під тестовим акаунтом:

```text
anna@group.local / User123!
```

6. Створити оголошення.

7. Перевірити пошук, фільтр, сортування, редагування та видалення.

8. За потреби перевірити security-сценарії через `security-regression.http`.

## Примітки

- База SQLite створюється автоматично у папці `data`.
- Якщо потрібно почати з чистої бази, можна зупинити сервер і видалити файл `data/posts-board.sqlite`.
- Після видалення бази при наступному запуску знову створяться таблиці й тестові користувачі.
- Frontend не потрібно відкривати через `file://`, краще використовувати Live Server або `python -m http.server 5500`, щоб CORS працював коректно.
